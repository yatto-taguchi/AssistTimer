# リスクベース開発・チェック体制ルール (Issue #17 常時適用)

本リポジトリ（Assist Timer）では、完了速度と安全性を両立するため、変更のリスクに応じてチェック体制を切り替える（2026-11-13 オーナー決定・Issue #17）。

高リスク変更時のサブエージェント定義は **[`.agents/skills/salon-multi-agent-dev/SKILL.md`](../skills/salon-multi-agent-dev/SKILL.md)** を参照すること。

---

## 1. チェック（レビュー）を通す対象（高リスク変更のみ）
**本番の挙動を変える高リスク変更のみ**、マルチエージェントによるチェックを実施する：
- **Issue #14** の共有タイマー同期信頼性改善（および同期ロジック変更）
- **アラーム・通知まわり** の変更

## 2. チェック不要とする対象（テスト＋ビルドの通過で完了）
以下の **挙動を変えない作業** ではサブエージェントレビューを行わず、**テスト＋構文／ビルド確認の通過のみで完了** とする：
- **Issue #13** の診断ログ追加（挙動を変えない作業）
- **Issue #15 / #16** の無振る舞い変更のファイル分割（機械的整理）
- その他、本番の挙動を変えない作業全般

## 3. 高リスク変更におけるチェックの運用ルール
1. **上限 1 ラウンド**: チェック（事前確認および実装後の `qa-verifier` 検証）は **上限 1 ラウンド** とし、繰り返し差し戻しループを行わない。
2. **ブロッカー基準**: 作業をブロックして修正するのは **「本番で実際に壊れるもの（`BLOCKER`）」だけ** とする（修正後はテスト＋ビルド通過で完了）。
3. **仮定上のエッジケースの扱い**: 仮定上のエッジケース（`NOTE`）は完了報告のリストに残すに留めて作業をブロックせず、実際に問題が起きた時点で対応する。
